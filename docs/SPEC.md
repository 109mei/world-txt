# WORLD.txt（世界再定義）試作 仕様

## 1. 概要と、この試作で作った範囲

世界を定義している文章（WORLD.txt）を**自由に消す・書き換える・書き足す**ことで、人類文明を存続させるテキストベースの世界シミュレーション。スマホ縦画面のブラウザゲーム。

- プレイヤーが触れるのは文章だけ。選択肢も、書き換えの結果の予測も出さない。結果は時間を進めて世界を見るまでわからない
- 書いた文章は、世界が語彙から意味を読み取る（否定・量・頻度・例外・条件・「〜なしで」・「〜だけ」・「〜に強い」・英語）。**どんな文でも受け取る**：その行の新しい意味／新しい概念（1文にいくつでも）／別の行の書き換え／すでにある意味（重複）／意味のない文（理由つき）のどれかになる。**意味のない文では、世界は何も変わらない**（使うのは文字数と書換の力だけ）
- 技術・科学・経済の言葉（人工知能・半導体・反物質・ブラックホール・ベーシックインカム など）や、無茶な決まり（人は服を着ない・出会うたびに交わる・人を食べる など）も読み、現実の仕組みに沿った結果になる。辞書にない言葉も、語尾から種類を推し量る（「顔認証カメラ」は機械、「肺炎」は病気）
- 因果は現実の仕組みに沿わせる（例：植物が光だけで育つ → 農業の水＝淡水の約7割が浮く → しかし植物の蒸散が消え、陸の雨の約4割が消える）。想定外の変化には「なぜ？」を一文で添え、**どの一文から来たか（← 書いた文章）**を示す
- 見つけた読み取り・想定外の変化・出来事・危機・結末は**観測記録**に残り、世界をまたいで集まる
- **無限の世界**：目標の年がなく、文明が滅ぶまで続く。途中で危機（隕石・未知の病・破局噴火・世界大戦など）の知らせが届き、数年後に世界を襲う。何年続いたかを競い、長く続いた上位10件が**記録簿**（この端末のランキング）に称号つきで残る。「今日の世界」は日付から種が決まり、同じ日なら誰でも同じ世界
- **くり返す十年**：10年ごとに0年目へ巻き戻る世界。書いた文章は残り、同じ書き方なら同じ出来事がくり返す。破局の原因を突き止めて断ち、11年目へ抜け出す
- **時間の文は結末だけ**：時間を止める・くり返す・逆に流す・過去へ戻る・遥かな時を過ごす文は、その年のうちに特別な結末になる（時間を操れると、世界容量や書換の力の縛りが意味を失うため）
- **特別な結末**：宇宙・地球・重力・太陽・人類を消す、原子をまとめる力を消す、宇宙人が来る、星々へ移り住む、人が死ななくなる、などの書き換えは、専用のゲームオーバー／クリアになる。ふつうの滅び方にも、そのときの世界に合った名前がつく（「核の冬」「凍りついた星」「紙くずの星」「心の尽きた星」など）
- **実績**：世界をまたいで集まる59の実績
- **開ける世界は1つだけ**：別の世界を開くときは、遊んでいる世界を放棄してよいかを確かめる。別の画面（タブ）で同じ世界が開かれたら、古い画面は保存をやめる

## 3. ルール

### 3.1 世界の中身（1年ごと）

内部の状態（人口・農業・産業・発電・再エネの割合・石油の残り・物流・科学・生態系・CO2・気温・流行・免疫・病原体の強さ・作物の病気・食料の蓄え・社会の安定・幸福・国際緊張・戦争・失業・心・物価・世界整合性・世界容量）を、毎年つぎの順で進める。

1. 法則（読み取った意味）・行が運ぶ意味（書き足した概念・重ね書き）・組み合わせ・副作用・一時的な出来事から「係数」（食料の必要量・収量・雨・温室効果・兵器の破壊力・再エネの出力・心・お金の増え方・不運など57種）を組み立てる
2. 食料・水・エネルギーの釣り合いを計算する（食料＝農業の規模×収量×分配、足りない年は蓄えを取り崩す）
3. 農業と発電は需要に合わせて広がり・縮む（農家は収穫の過不足を見て動き、縮むと失業が出る）
4. 病気（うつりやすさ R と免疫）、人口（出生・老衰・飢え・渇き・暑さ・病気・戦争）、産業・失業・物流・科学、CO2 と気温（気候感度 CO2 倍増で約3℃、遅れて追いつく）、生態系、社会の安定・幸福・国際緊張、戦争（緊張が高いと始まり、長引くほど疲弊して終わる。激しさは兵器の破壊力で決まる）、心と物価、世界整合性
5. 遅れて効く副作用が育つ → 組み合わせの成立を知らせる → 出来事（条件と確率。災害は不運の係数で起こりやすさが変わる）→ 世界異常（整合性が 70 を下回ると起きうる）→ 危機（無限の世界）
6. 書換の力が戻る → 終わりの条件を確かめる（くり返す十年は巻き戻り）→ 人口と文明を記録する（リザルトの曲線）。世界史は新しい400件まで残す

- **心**（ふだん60）：心の健康と生きる張り合い。書き換えの概念（感情を持たない・何も忘れない・5億年ボタン・監視社会 など）と物価の高さで動き、ふだんの高さへゆっくり戻る。心の高さは幸福・安定・産業・科学・出生に効く。20以下で滅ぶと「心の尽きた星」
- **物価**（はじめ1）：お金の増え方（書き換え・出来事で上がる割合）で上がり、増え方がなければ1へ戻る。高いほど分配・産業・安定・幸福・心が下がる。お金のない世界では意味を持たない。千倍を超えて滅ぶと「紙くずの星」

書き換えただけでは世界の様子は計算し直さない（結果は時間を進めて初めてわかる）。世界容量と整合性の元になる重さだけは、すぐ変わる。

### 3.2 書き換え（命令）

どの命令も「書いたあとの WORLD.txt」を先に組み立て（`planWrite`）、世界容量を確かめてから書き込む。書き換え画面の見積もり（`costAfter`）も同じ組み立てを使う。

| 命令 | 内容 | 書換の力 |
|---|---|---|
| 行を書き換える | 既存の法則の文章を好きに書き換える。読み取った意味に切り替わる。同じ文に書いた新しい概念も、その行が運ぶ（「人間は数日に一度食べ、空を飛べる。」）。**別のものについての文に書き換えると、元の定義は消え、新しい意味がその行に宿る**（「争いは戦争になりうる」→「人間は空を飛べる」＝戦争が起こらない＋空を飛ぶ）。主語が同じなら元の意味は残る | 1 |
| 行を消す | 文章を空にする。その法則の「削除したときの意味」になる。言葉を消しただけで話題の言葉がなくなった文や、述語を消して「〜を」で途切れた文（「火は燃えるものを」）も削除 | 1 |
| 書き足す | 新しい一文を足す。言い回し集（1文にいくつでも）→ 既存の行の書き換え → あとで読む言い回し（願い・世界そのものへの命令）→ 種類ごとの読み取り（ほかに何も読めなかったときだけ）の順に読む。**既存の行の話で、その行がまだ書き換えられていなければ、その行の書き換えとして読む**（「雨がたくさん降る。」→ 水の循環の行が「雨が増える」に）。すでに書き換えた行の話なら**重ね書き**（同じものに2つの定義。整合性が少し下がる） | 1 |
| 書き足した行を書き換える・消す | 同上 | 1 |

- 同じ意味の定義は重ねられない（書換の力は使わない。「◯行目に、すでに同じ意味の定義がある」）
- 筆の位（3.15）で書けないものは止める（書換の力も世界容量も使わない）：封じられた行（書き足した文がその行に溶け込む・重ねて書く場合も）、余白のない書き足し、いまの筆には重すぎる概念（行の書き換えに運ぶ概念も同じ）
- 書換の力：最初に3、5年ごとに1戻る（最大5）。極小世界は最初に4、3年ごとに1（最大6）。くり返す十年は巻き戻るたびに1戻る
- **世界容量＝ WORLD.txt の文字数**：行の重さは、その文章の文字数（句読点・かっこは数えない）と、行が運ぶ新しい概念の重さ（文字数に換算して6〜36字）の合計。初めの WORLD.txt は550字。重くなる書き換えは上限を超えられない（軽くなる書き換えはいつでもできる）
- 同じものについて短く言い換えれば、意味を変えずに字数を減らせる（例：「人間は毎日食事を必要とする。」13字 →「人は毎日食べる。」7字）
- 世界整合性：読み取った意味ごとの「無理さ」の合計、1行に詰め込んだ概念（2つ目から1つにつき4）、重ね書き（1つにつき6）で下がる。世界容量が 95% を超えても下がる。**意味のない文は下げない**（世界は何も変わらない）。辻褄の合う組み合わせ（例：季節がない＋気温が変わらない＝「常春の星」）は、揺らぎを少し戻す

### 3.3 読み取り（`src/core/interpret.ts`）

形態素解析はせず、文章から手がかりを取り出して、法則ごとの規則（`laws.json` の `match`）と言い回し集（`phrases.json`）に当てはめる。英語と言い換え（ウイルス→病原体、CO2→二酸化炭素、ごはん→食事、ChatGPT・AI・LLM→人工知能、GPU→半導体、仮想通貨・bitcoin→暗号資産 など。`lexicon.json`）は、読む前に日本語の言葉へそろえる。同じ文章からは、いつも同じ読み取りになる。

| 手がかり | 例 |
|---|---|
| 否定（元の文との反転） | 〜ない・〜しない・不要・消える・存在しない（「少ない」「〜しなければならない」は否定にしない。「ほとんど〜ない」は「少ない」） |
| なくなることの打ち消し | 「終わらない」「尽きない」「滅びない」「絶滅しない」は否定ではなく「続く」（「戦争は終わらない」は戦争を消さない） |
| 二重否定 | 「Xなしでは〜ない」「Xしか〜ない」の「ない」は数えない（「植物は水なしでは育たない」は元の意味） |
| 場所を限った否定 | 「作物は海では育たない」は、そのほかでは元のまま |
| 量 | 少し・わずか・ゆっくり・弱く／多く・倍・大量・強く・速く。強調（とても・もっと）は向きを持たず、ついた言葉の向きを強める（「とても少ない」は少ない）。「〜に強い」を「とても」で強めると強さ（「暑さにとても強い」＝暑さで弱らない） |
| 頻度（毎日＝1） | 数日に一度・二日に一度・隔日・週に一度・一日に三回・時々 |
| ないもの・それだけのもの | 「Xなしで」「Xがなくても」「Xを必要としない」「Xを使わずに」「AもBも必要としない」／「Xだけ」「Xのみ」「Xしか〜ない」 |
| 強さ・弱さ | 「〜に強い」「〜に負けない」／「〜に弱い」 |
| 例外・条件 | ただし〜・〜を除く・〜以外／〜のとき・〜を超えると・〜なら・〜の日・〜する限り（「限りがある」は条件ではない） |
| 問い | 〜か？（書き足した問いは読まない） |
| 何についての文か | 行ごとの主語（`subject`。元の文の主語は自動）と話題の言葉（`topic`） |
| 述語そのもの | 規則の `rest`：主語の「は」「が」より後ろが、まるごとその言葉のときだけ（「猫はない」「猫はもういない」）。「猫は泳がない」の「がない」、「猫は鳴かなくなる」の「なくなる」は拾わない |

- **言葉は「その言葉として」数える**：別のものを指す言葉の一部は数えない（「人工知能」「宇宙人」の「人」、「冬眠」の「眠」、「魔法」の「法」、「光合成」の「光」）。その行の知っている言葉（「人間」「睡眠」）と、世界の知らない言葉（「死亡」）の一部は数える
- **主語が別のもの**の文（「生き物はいつか死ぬ」→「人工知能は死なない」）は、その行の意味としては読まない
- **新しいもの**を持ち込んだ文（「雨はお菓子になる」の菓子、「人間は魚を食べない」の魚）や、**その行の知らない動き**の文（「人間は食事を愛さない」の「愛」）は、元の意味の言い換えにも、その行の削除にもならない。「消える」「変わる」「止まる」「起きる」など、どの話にも使う動きは除く
- 行の書き換えの順：空なら削除 → 元の文 → 主語が別のものなら読まない → 場所を限った否定は元のまま → 削除以外の読み取り → 言葉を消しただけの文 → 削除の規則 → 手がかりのない同じものについての言い換え（元の意味）→ 意味のない文
- いまの世界ですでに起きていること（「地震が起きる」「火山が噴火する」「戦争が起きる」）は、世界を変えない。変えるのは「大地震が起きる」「大噴火が相次ぐ」「戦争が続く」のように、多さや大きさを言った文
- **意味のない文**には理由を返す（`noiseOf`）：記号だけ／短すぎる／問いかけ／知らない言語／知らない言葉（「ポポポ」「ドラゴン」）／意味がつかめない。どれも世界は何も変わらない（書き換えた行の意味は、書き換える前のまま）
- **日常の言葉の種類**（`lexicon.json` の `kinds`、18種・1114語）：食べ物・飲み物・動物・人・植物・機械・病名・物質・天体・気象・場所・職業・感情・体の部分・服・文化・学問・しくみ。その種類の行の話として読む（「人間は毎日パンを必要とする」は食事の行の言い換え）が、種類より狭いので、打ち消しても行全体は消さない（「猫は存在しない」で動物の行は消えない、「人間は砂糖を必要としない」で食事の行は消えない）
- **辞書にない言葉**は語尾から種類を推し量る（`suffixes` の88と、2文字以上の辞書の言葉：「クーロン力」→力、「肺炎」→病名、「野良猫」→動物、「顔認証カメラ」「大規模言語モデル」→機械）。一つの言葉は一つの種類にだけ読む（「ロボット犬」は犬の一つ）。辞書の言葉は、まるごとと中心（後ろ）の言葉だけを種類に入れる（「量子コンピューター」は機械だが「量子」は機械ではない）。ひらがなの入った言葉（「天の川」「天ぷら」）はまるごとだけ（「川」は天体ではない）
- **種類ごとの読み取り**（言い回しの `generic`）：「{X}がいなくなる」「{X}が増える」「{X}がふしぎな力を持つ」「{X}が世界を治める」など23。ほかのどの言い回しにも法則にも読めなかったときだけ当てる（「服は存在しない」を「人が服を着ない」と重ねて読まない）。名前の「{X}」は書いた人の言葉で埋める（「SNSがなくなる」「ChatGPTがなくなる」「がんがなくなる」）
- **1文字の漢字の言葉**は、ものの名前の一部なら、その名前の中心（後ろ）のときだけ数える（「日光」は光の一つ、「老人」は人の一つ。「石油」の「石」、「砂糖」の「砂」、「光合成」の「光」は数えない）
- **主語の規則**（`subject`）：言い回しの規則に主語を書ける。主語は「の」より後ろ（「人間の仕事が消える」の主語は「仕事」。ただし辞書の一つの言葉「天の川」は切らない）、言葉として出てくるときだけ（「宇宙人は存在しない」の主語は「宇宙」ではない）。ひらがなの主語（「がん」「ねこ」「もも」）も削らずに読む
- **存在の行**（`exists`）：「太陽は存在しない」「風が消える」のように書き足すと、その存在を表す行（太陽・風・病原体・お金・戦争 など19行）の削除として読む。なくなることを言う言葉（消滅・滅亡・絶滅・滅びる）も否定として読む
- **死を望む**：「人は死を望む」「人は生きることを望まない」「人類は滅びを望む」「人は消えたい」は、人が生きる望みを失う（死亡が大きく増え、心が尽きる）。数年のうちに人が絶え、「心の尽きた星」で終わる（食料危機で1年）。「人は死を望まない」「人は消えたくない」は、いまの世界のまま（意味のない文。「人は死なない」とは読まない：その行の知らない動き（「望まない」）を打ち消した文には、打ち消しだけを手がかりにする規則を当てない）
- **死と老い**：「人は死なない」「人類は不死身だ」「人間は永遠の命を持つ」「人は死んでも生き返る」は、人間だけが死ななくなる（老いは続く）。「人は不老不死である」「人は老いず、死なない」は、老いも死も止まる。「生き物は死なない」「死は存在しない」は、生き物すべてから死がなくなる。「人は歳をとらない」「寿命は無限だ」は老いがなくなり、「人間は千年生きる」は老いがゆっくりになる。元の意味と同じことを打ち消しで言った文（「人は永遠に生きない」）は、元の意味のまま
- **専門の言葉と無茶な決まり**（言い回しの例。どれも「なぜ？」つきの出来事で結果を知らせる）

| 分野 | 書いた文 → 読み取り（結果） |
|---|---|
| 人工知能 | 世界を支配する → 機械が世界を治める／人類に反乱する → 機械が人類に牙をむく（滅びると「機械に敗れた星」）／人間を超える・シンギュラリティ → 人工知能が人を超える（科学が伸び、富が集まる）／心を持つ → 機械が心を持つ（機械の権利をめぐる争い）／人は機械と結婚する → 人と機械が愛し合う（生まれる子が減る） |

### 3.4 原因と観測記録

- 副作用のニュースには、それを最も強く育てている行、出来事には条件に書かれた行（書き換えた法則・書き足した言い回し・副作用の元）、世界異常には世界を最も揺らしている行、防いだ・弱めた危機にはそうさせた行を「原因」として付ける。プレイヤーが書き換えていない行は原因にしない
- 観測記録の id：`r:法則.読み取り`／`p:言い回し`／`t:副作用`／`e:出来事`／`k:危機`（`.softened` 弱めた・`.averted` 防いだ）／`c:組み合わせ`／`a:世界異常`／`g:タグ`／`end:ステージ.結末`。世界ごとに `GameState.found` に見つけた順で残し、命令のたびに進み具合（`progress.discovered`）へ移す

### 3.5 乱数

種つきの疑似乱数（mulberry32）を GameState に持つ。出来事の確率・戦争の開始・世界異常・危機（どの危機が来るか・次の知らせまでの年数）だけで使う。同じ種・同じ書き換えなら同じ世界になる。今日の世界の種は日付（YYYY-MM-DD）から作る（`dailySeed`）。くり返す十年は、巻き戻るときに乱数も0年目の状態に戻す。

### 3.6 終わり

- CLEAR：目標年数に到達（無限の世界にはない）、または特別な結末（クリア）
- 失敗：人口がステージの下限を下回る／文明の点数 25 未満が3年続く／世界整合性 12 未満／世界容量の上限超えが3年続く、または特別な結末（ゲームオーバー）
- くり返す十年では、くり返しがほどけるまで、人口や文明が崩れた年は失敗にならずに巻き戻る

### 3.7 無限の世界と危機（`crises.json`）

- 危機は10種：巨大隕石・未知の病・破局噴火・太陽嵐・大干ばつ・寒い時代・作物の疫病・世界大戦・世界恐慌・巨大地震。どれも現実の根拠（なぜ？）を持つ（例：約6600万年前の小惑星の衝突、1815年のタンボラ山の噴火と「夏のない年」、1859年のキャリントン・イベント）
- 知らせ：10年目に最初の知らせが届き（重大な知らせなので、時間はそこで止まる）、3〜6年後に襲う。毎年「あと何年」を知らせる。直前の危機は続けて来ない
- 襲う年の世界の定義しだいで、**防げる**（`avertedBy`：例 隕石は「隕石は地球に落ちない」「災害は起きない」、太陽嵐は「電気は導線なしで伝わる」、世界大戦は戦争の行の書き換え）・**弱まる**（`softenedBy`：強さが半分。例 兵器が人を傷つけない、人が村に分かれて暮らす）・**そのまま襲う**。知らせは世界の出来事で、書き換えの結果の予測ではない。どう書けば防げるかはプレイヤーが考える
- 防ぐ文を書き重ねると世界整合性が下がる（例：「災害は起きない」は無理さ18、副作用「運ばれない土」）。危機が去ったら戻すかどうかも、プレイヤーの判断
- 強さは年とともに増し（1＋0.025×年、最大4）、次の知らせまでの年数は縮む（8年から、年0.04ずつ、最短3年。0〜3年ずれる）
- 終わり：人口50億未満／文明の崩壊が3年続く／世界整合性の崩壊／世界容量の限界超えが3年続く、または特別な結末（ゲームオーバー）。クリアの結末でも世界は続く

### 3.8 特別な結末（`endings.json`）

- **その場で終わる結末**（trigger）：条件が決まった年数続くと、その年に世界が終わる。大きい priority から確かめる。2年以上かかるものは、始まった年に「あと何年」を知らせる（どの一文から来たかも）

| 結末 | 種類 | 条件 | 年数 |
|---|---|---|---|
| 無 | ゲームオーバー | 宇宙が消える | 1 |
| ほどけた物質 | ゲームオーバー | 電気の力（クーロン力）・原子・電子・量子・光子が消える | 1 |
| 崩れる原子核 | ゲームオーバー | 原子核をまとめる力・中性子・クォークが消える | 1 |
| 呑まれた星 | ゲームオーバー | ブラックホールが地球に近づく | 1 |
| 光になった世界 | ゲームオーバー | 反物質があふれる | 1 |

### 3.9 実績（`achievements.json`）

- 条件は3つの組み合わせ：遊んでいる世界の条件（core の条件の書き方。書換の回数・書き足した行・1行の概念の数・意味のない行・重ね書き・防いだ危機・世界異常・組み合わせ・結末・今日の世界 などの量も使える）／世界の終わり方（クリア・失敗・どちらでも）／これまでの進み具合（救った世界の数・遊んだ世界の数・観測記録・無限の世界の最長・見た特別な結末の数・実績の数・放棄した世界の数）
- 書き換え・時間を進める・世界を開く・放棄するたびに確かめ、得たものは `progress.achievements` に残る。隠し実績（特別な結末など）は得るまで名前も伏せる

### 3.10 開ける世界は1つだけ

- 遊んでいる世界（終わっていない世界）は1つ。別の世界を開くと、前の世界は放棄され、放棄した数（`progress.abandoned`）が残る。終わった世界からは、放棄にならずに次の世界を開ける
- 別の画面（タブ）で同じセーブが書き換えられたら（`storage` の知らせ）、古い画面は保存をやめ、読み込み直しを促す（2つの世界が混ざらないように）

### 3.11 くり返す十年（`stages.json` の `loop`）

- 10年目の終わりに、その10年のうちに大戦が起きていれば、あるいは文明（45以上）が保たれていなければ、世界は0年目へ戻る。くり返しの中で人口や文明が崩れた年も、その年に巻き戻る（「文明が崩れたその年、時が巻き戻り…」）
- 巻き戻るのは世界の側の様子（人口・環境・副作用・出来事の印・乱数・暦）。書いた WORLD.txt・観測記録・世界史は残る。乱数も戻るので、同じ書き方なら同じ出来事が同じ順でくり返す
- 巻き戻るたびに世界の頁が擦り切れて世界容量が30字減り、書換の力が1つ戻る（何もしないと3回巻き戻ったところで世界容量が尽きる）
- この世界の10年：北の永久凍土がとけて古い病原体が目覚め → 病で働き手が減って北の穀倉地帯の収穫が落ち → 食料を奪い合う大国どうしの戦争が始まる。どこで断つかはプレイヤーが見届けて考える（病が人にうつらない・動物から人にうつらない など）
- くり返しをほどくと11年目へ進み、30年を生き延びれば CLEAR

### 3.12 記録簿（無限の世界のランキング。`src/store/ranking.ts`）

- 無限の世界が終わるたびに、文明が続いた年数・今日の世界か・世界の名前・結末・書き換えの回数・防いだ危機の数を記録し、上位10件を `progress.ranking` に残す（この端末の中だけ。サーバーはない）
- 並べ方：年数の長い順 → 防いだ危機の多い順 → 書き換えの少ない順 → 先に記録した順
- 称号（`indicators.json` の `ranks`）：灯をともす者（0年）・灯を守る者（20年）・半世紀の書き手（50年）・一世紀の書き手（100年）・時代の書き手（150年）・伝説の書き手（200年）・神話の書き手（300年）。リザルトに称号と順位、共有の文章にも称号を添える

### 3.13 書き換えた年の世界（効き始めの知らせと、書き換えの勢い）

書いた一文は、時間を進めた最初の年に世界のあり方になる。

- **効き始めの知らせ**：概念（223）と法則の読み取り（元の文を除く全部）は、どれも「効き始めた年の知らせ」（`onset`）を持つ。時間を進めた年に、去年のあいだ世界に効いていた意味（`GameState.inEffect`：`o:法則.読み取り` と `p:概念`）と今の意味を比べ、新しく効き始めた意味を「世界が書き換わった」として知らせる（例「人々が空を飛び始めた。道より空を行く人が増えていく ←『人間は空を飛べる。』」。{X} は書いた文の主語）。書いただけでは知らせない。消した概念は「『人間が空を飛ぶ』世界は、終わった」、元の文に戻した行は「『…』が、世界に戻った」と知らせる。世界史にも残す
- **書き換えの勢い**：書き換えると、ゆっくり動く量（産業・失業・生態系・社会の安定・幸福・国際緊張・心・世界整合性・気温）の向かう先が動く。書き換える前と後の向かう先の差を `GameState.impulse` に貯め、次の1年の初めに `balance.impulse` の割合だけすぐに動かす（残りは、ふだんの速さで追いつく）。気温の変わらない世界では気温は動かさない。向かう先は `src/core/model.ts` の `targetsOf`（1年の計算と同じ式）
- 測ると：概念ひとつ・読み取りひとつ（389）を書いて1年進めると、何も書かない世界と比べて、状態語も知らせも変わらないものは 0（以前は 110〜171）。状態の点数の動き（中央値）は、食料危機 9→14・気候危機 7→12・無限の世界 6→8
- 結果の画面は、状態語は変わらなくても、1年に 1.5 点以上動いた項目を矢印で見せ、人口の表示が変われば「人口 約80億人 → 約81億人」と見せる

### 3.14 世界の情景（`src/store/scene.ts`・`src/ui/scene/`・`src/data/scene.json`）

世界のタブのいちばん上の挿し絵。今の世界の状態と、書き換えたことのすべてを、そのとおりに描く。

- **状態から**：町の灯り（人類とエネルギー）、塔の高さと崩れ（文明）、畑（食料）、森と獣と鳥（生態系）、川と海（水）、煙（産業）、霧（健康）、暑さの揺らぎ・雪（気候）、戦火と兵士（戦争）、国境の壁（世界情勢）、群衆と松明（社会の乱れ）、灯籠（社会の安定）、研究所の光（科学）、車と船（物流）、風車と太陽光（再生可能エネルギー）、油井（化石燃料）、墓標（失われた命）、暗い色（心）、世界の揺らぎ（世界整合性）
- **書き換えから**：概念と法則の読み取りは、どれも情景での描き方（`scene`：描く要素と強さ・言葉の絵・石碑）を持つ。描く要素は190（空を飛ぶ人・二つの太陽・ブラックホール・宇宙人の船・ロケット・恐竜・巨人・小さな人・ゾンビ・機械の体・独裁者の像・一つの旗・海底の町・干上がった海・止まった時間・逆さの時間・世界の格子 など。`SCENE_MOTIFS`）。書き換えから来たものはインクの色で描く。時間を進めて世界に効き始めてから描く（`inEffect`）
- **言葉の絵**：「{X}がいなくなる」「{X}が増える」「{X}が世界を治める」「{X}がふしぎな力を持つ」は、書いた言葉（猫・パン・スマホ など）を、その言葉の種類の形（獣・植物・食べ物・機械・病・星・天気・土地・仕事・気持ち・体・服・文化・学問・しくみ・人 など19）と名前で空に描く。消えた（点線と斜線）・増えた（三つ）・治める（冠）・ふしぎな力（光）
- **石碑**：絵にしにくい決まり（気温が変わらない・病原体が姿を変えない・エネルギー保存 など）は、その概念の印を刻んだ石碑として手前に並べる
- **ほかに**：副作用（育ち具合に合わせて）、知らされた危機の兆し（襲う年が近いほど強い）、その年の重大な出来事と世界異常（その年だけ）、世界の結末（`scene.json`）
- **動き**：雲が流れ、雨と雪が降り、人が歩き、空を飛ぶ人が横切り、風車が回り、炎が揺れ、波が寄せ、船が進み、ロケットが昇る。時間が止まった世界では止まり、逆に流れる世界では逆に、速い世界では速く動く。地震の世界は揺れ、揺らいだ世界は乱れ、心の暗い世界は色が抜ける。画面の外に出た情景と、「情景を動かす」を OFF にしたときと、動きを減らす設定の端末では動かない
- **時間を進めた年の塗り替え**（結果の画面の情景）：時間を進める前の絵（`sceneFrom`）を上に重ね、インクの縁が左から右へ塗り替えていく（約1.7秒）。去年の絵になくて今年の絵にあるものは（書き換え・副作用・危機・状態のどれから来たものでも）、塗り替えが通り過ぎてから、そのものらしく現れる（`src/ui/scene/common.tsx` の `ENTER`）：太陽はふくらむ・遠のいて縮む、二つ目の太陽・ロケット・海底の町は下から昇る、宇宙人の船・天の光・糸は降りてくる、隕石は斜めに落ちる、巨大な塔・森・像・原子炉は根元から伸びる、噴火ときのこ雲は噴き上がる、砂丘・氷・干ばつ・虹・夜の側は広がる、獣・恐竜・ロボット・兵士は歩いてくる、空を飛ぶ人・鳥は飛び立つ、言葉の絵は落ちて弾む、石碑は地面から現れる、光の消えた病院・研究所は明滅する、海面は上がる。もとからある物の姿を変えるだけのもの（枯れる・廃墟になる・重くなる）は、塗り替えだけで見せる。**なくなったもの**は、前の姿をしばらく残してから、そのものらしく消える（月は欠けて消え、太陽は沈む・吸い込まれる・薄れる、海は水が引いて海の底が現れ、森は崩れ落ちて切り株が残り、人と獣と雲は薄れ、町の灯りは明滅して消える）。同じ年に何度も見せない。動きを止めているとき・動きを減らす設定では、塗り替えも現れ方も見せずに今年の姿を描く
- **どんな組み合わせでも矛盾のない絵にする**（`scene.json` の `exclusive` と `hides`）：反対どうし（森が茂る・森がない、雲が多い・雲がない、動物がいない・恐竜 など44組）は一つだけ残す（書き換えから来たもの → 後に書いたもの → 強いもの の順）。大きな欠け（海がない・人がいない・太陽がない・お金がない・森がない・夜が明けない・夜が来ない）があれば、それを前提にする絵（潜る人・空を飛ぶ人・二つの太陽・金貨・山火事・星 など）は描かない。広場の人の姿（機械の体・光輪・仮面 など22）は、いくつ重なってもどの姿も一人は表れるよう、その年に現れたもの・書き換えから来たものを先に割り当てる。一つだけで弱く描かれる要素（副作用が育ち始めたときなど）も、途中の姿（月が薄れる・海が少し引く・町のはずれに小屋が建つ など）で必ず絵を変える
- テスト（`tests/scene.test.ts`・`tests/scene-render.test.ts`）：どの要素も一つだけ書けば、強くても弱くても絵が変わる。書き換え・副作用・状態をでたらめに重ねた600の世界でも絵は壊れず（NaN などがない）、反対どうし・大きな欠けの決まりを守り、描く物の数には限りがある。160の世界で、書き換えから来たものはどれも絵に表れる。時間を進めた年は塗り替え、なくなったものは消えていく姿を描く。概念と法則の読み取りのすべてが情景のどこかを変える、書いただけでは描かない、その年だけ現れ方を見せる、言葉の絵は言葉の種類の形で描く、副作用・危機・結末も描く

### 3.15 筆の位（書き換えられる範囲。`src/core/access.ts`・`src/data/access.json`）

救った世界の数で筆の位が上がり、書き換えられる範囲が広がる。世界を開くときに、位とステージから範囲を決めて `GameState.access` に持たせ、core の書き換え命令が確かめる（遊んでいる途中で位が上がっても、その世界は変わらない）。

| 位 | 救った世界 | 範囲（書き換えられる行の分野） | 場所（書き足せる行） | 対象（書ける概念の重さ） |
|---|---|---|---|---|
| 見習いの筆 | 0 | 暮らし（人間・老化・出生・睡眠・死・食料・農業） | 1行 | 暮らしのこと（無理の大きさ18まで） |
| 写字生の筆 | 1 | ＋生き物（植物・動物・病気・免疫・医療・環境） | 2行 | 大きな願い（22まで：病気がなくなる・老いない・瞬間移動 など） |
| 書記の筆 | 2 | ＋社会（教育・科学・工業・国家・貨幣・戦争・犯罪・幸福） | 3行 | 時間と体のこと（30まで：時間が止まる・死なない・太陽が二つ など） |
| 改稿者の筆 | 3 | ＋力（火・石油・エネルギー・電気・原子）＋大地と空（温度・大気・二酸化炭素・水・海・地球・太陽） | 5行 | 物の理の根本（40まで：重力・原子核の力・自転が止まる など） |
| 創世の筆 | 5 | すべて | 限りなし（世界容量の許すかぎり） | 世界そのもの（宇宙・地球・人類が消える など、何でも） |

- **その世界の危機に関わる行は、位にかかわらずはじめから開いている**（`access.json` の `stages`：食料危機なら食事・農業・植物・動物・水・国家、気候危機なら温度・大気・二酸化炭素・海・太陽・地球・石油・植物・戦争・病気・犯罪・貨幣 など。極小世界はすべて）
- **無限の世界では、危機の知らせが届くと、その危機を防ぐ・弱める行の封が、襲うまでのあいだだけ解ける**（`crises.json` の `avertedBy`・`softenedBy` の行。定義のタブに「危機の知らせで、封が解けている行がある」）
- 封じられた行は書き換えも削除もできない。書き足した文が封じられた行の話なら、その行の書き換えとして読んでも止める。書き足した行の書き換え・削除は、余白を使わない
- 範囲を渡さずに作った世界（シミュレーター・テスト）と、版7までのセーブの世界は、すべて自由
- 確かめる：`npm run ranks`（どのステージも、はじめて遊べる位で作戦が止まらず、クリアできる作戦がある）と `tests/access.test.ts`

### 3.16 世界の終わりまで（`src/store/view.ts` の `limits`）

世界のタブで、4つの終わりの線まであとどれぐらいかを見せる（項目が下がっているのはわかるが、あとどれぐらいかがわからない、に答える）。

- 人口（ステージの人口の下限。例：60億人を割ると人類は終わる）・文明（下限を割ったまま3年で崩壊）・世界整合性（崩れると世界は意味を失う）・世界容量（上限を超えたまま3年で終わる）
- 帯：終わりの線を左から2割の所に引き、その左は斜線（終わり）。線からの近さ＝（今 − 線）÷（安全 − 線）。安全は、人口ははじめの人口、文明と世界整合性は状態語が「安定」以上になる所、世界容量は状態語が「安定」までの使い方
- 言葉：近さ 0.55 以上「遠い」、0.3 以上「まだある」、0.12 以上「近い」、0 以上「目前」、下回れば「越えた」（`indicators.json` の `limits`）。ただし、このままなら1年以内に線に届くなら「目前」、3年以内なら「近い」、6年以内なら「まだある」までに抑える（遠くても速く近づいていれば、言葉は急ぎを表す。帯の位置は今の近さのまま。`soon`）。目前・越えたは線が脈打つ
- 線を越えたら「あと◯年で終わる」、線へ向かっていれば「このままなら約◯年」（去年の変わり方が続いたら何年で線に届くか。20年より先なら出さない）。書き換えの結果の予測ではなく、去年の動きをのばしただけ
- 数は現実の単位（億人・字）だけ。点数は出さない

## 6. セーブ

- `src/save/SaveStore`（localStorage。書き込みは Promise なので Dexie に差し替えられる）
- 版番号 `saveVersion`（今は 5）。版 0（設定・進み具合なし）→ 1、版 1（観測記録なし）→ 2、版 2（無限の世界の記録なし）→ 3、版 3（実績と放棄した世界の数なし）→ 4、版 4（記録簿なし。これまでの無限の世界の記録から、長く続いた順に上位10件を作る）→ 5 の変換あり。遊んでいる世界の形は `GameState.schema`（今は 8。8：書き換えられる範囲・筆の位 `access`（古い形は、すべて自由として補う）、7：去年効いていた意味 `inEffect` と書き換えの勢い `impulse`（古い形は、今の意味で補う。読み込んだだけで「効き始めた」と知らせない）、3：行が運ぶ意味 `carried`、4：危機 `crisis`・`nextCrisis`・`crises` と今日の世界 `daily`、5：結末 `ending` と、特別な結末の続いた年数 `endingYears`、6：世界容量を文字数で数える（版5までの重さは ×6−6 で文字数に直す）・心・物価・くり返す世界 `loop`）で、古い形は読み込むときに `upgradeState` が補う
- 内容の版が変わって消えた法則・言い回しは、読み込むときに取り除く
- 読めないセーブは消さずに `world-txt/save.broken` へ残す。遊んでいた世界だけが壊れていれば、その世界だけを手放して設定と記録は残す（タイトルで知らせる）
- **控え**：保存するたびに、ひとつ前のセーブを `world-txt/save.prev` に残す。最新のセーブが読めない、または遊んでいた世界が壊れていたら、控えから読む（戻るのは直前の1手だけ。タイトルで知らせる）
- **空きが足りないとき**：控え・壊れたセーブの控えの順に空けてから保存し直す。それでも保存できなければ、画面の上に「保存できなかった…メニューの『セーブを書き出す』で控えをとっておく」と出す（閉じられる。次に保存できたら消える）。保存できない画面（プライベートブラウズなど）では、はじめにそう知らせる
- **大きさ**：長く遊んでもセーブは小さい（213年続いた無限の世界で約62KB。400の世界・約9000年を遊んで記録を積み上げても約27KB。世界史は新しい400件まで）。端末の保存領域（約5MB）よりずっと小さい。読み込むセーブは200万文字まで
- 端末の空きが少なくなってもブラウザに消されにくいよう、最初に画面に触れたときに、保存を残してもらうよう頼む（`navigator.storage.persist()`。できるブラウザだけ）
- iPhone の Safari は、しばらく開かなかったサイトの保存を消すことがある。大事な記録はメニューの「セーブを書き出す」で控えをとる
- 保存する物：設定（BGM・効果音・音量・情景を動かす・詳細分析）、進み具合（CLEAR したステージ・最高記録と最少の書き換え回数・遊んだ世界の数・観測記録・無限の世界の記録30件・記録簿10件・実績・放棄した世界の数）、遊んでいる世界（GameState まるごと。世界は1つだけ）
- 別の画面（タブ）で同じセーブが書き換えられたら、古い画面は保存をやめる（`storage` の知らせ）
- 書き出し・読み込み：メニューから（`WTXT1.` ＋ Base64。セーブの形でない文字は読み込まない。上書きは2度押しで確かめる）
- 書き換え・時間を進めるたびに自動で保存。閉じていた間の進行はない（ターン制）

## 7. 操作

- タップ：項目・行・ボタン（押せる物は44px以上。小さなチップは押せる範囲を広げてある）
- 文字入力：書き換え画面の編集欄（最大80字）。スマホのキーボードが出ても、書き換えのシートはキーボードの上に載る（Android は `interactive-widget=resizes-content`、iPhone は visualViewport）。入力欄の文字は16px以上（iPhone が拡大しない）
- 入力の補助：編集欄の下の言葉（〜ない・少し・とても・だけ・なしで・ただし・その行の言葉）を押すと、カーソルの位置（選んだところ）に差し込む。「〜ない」は文の終わりの述語を打ち消しの形にする（「必要とする」→「必要としない」、「育つ」→「育たない」。`src/ui/wording.ts`）。選択肢や結果の予測ではなく、打つ手間を減らすだけ
- 時間：「▶ 1年」だけ（1回で1年）。時が流れる演出はタップで飛ばせる。結果の画面の「▶ 次の1年」で、続けて進める（結果の画面のボタンは、いちばん下に留まって隠れない）。1年でも、ほとんどの年で状態語か知らせのどちらかが変わる（ステージと作戦で測って81〜100%の年。何も変わらない年が続いても、長くて4年）ので、10年ずつにはしない（危機の知らせから襲来までの3〜6年を飛び越えてしまうため）
- 取り返しのつかない操作（セーブの上書き・この世界をあきらめる）は2度押し
- 長押し・右クリックで、文字の選択・コピー・画像の保存などのメニューを出さない（`src/ui/touch.ts` と CSS。書き換えの編集欄とセーブの読み込み欄だけは、選んで貼り付けられる）

## 10. 安全（セキュリティ）

- **読み込めるものを絞る決まり（CSP）**：公開用のビルドの index.html に meta で入れる（`vite.config.ts`。GitHub Pages では応答の見出しを設定できないため）。スクリプト・通信はこのサイトだけ、書体は Google Fonts だけ、画像は自分・data・blob（共有画像）だけ。埋め込み・フォームの送り先・プラグインはなし。開発中の Vite はその場でスクリプトを差し込むので、開発用のサーバーには入れない
- **文字列からコードを作らない**：eval・new Function を使わない。Zod も jitless（`z.config({ jitless: true })`）で動かし、CSP に触れない。e2e で、遊んで結果の画像を保存するまでに CSP に触れないことを確かめる
- **書いた文章は文字として出す**：React がすべて文字として出す（HTML として読まない）。innerHTML などは使わない
- **よそへ住所を伝えない**：`<meta name="referrer" content="no-referrer">`（書体を読み込むときに、このページの住所を Google へ送らない）
- **読み込むセーブを疑う**：大きさ（200万文字まで）・文の長さ・数に上限を設け、Zod で形を確かめる。オブジェクトの仕組みに触れる鍵（`__proto__`・`constructor`・`prototype`）は読むときに取り除く。書き出したテキストの読み込み（別の端末からの引き継ぎ）も同じ道を通る
- **テスト用の窓口**（`?debug=1`）は、開発中とテスト用のビルド（`vite build --mode e2e`）だけ。公開用のビルドには入れない（GitHub Actions で、公開するビルドに入っていないこと、CSP が入っていることを確かめる）
- **公開の仕組み**：GitHub Actions は必要な権限だけ（読み取り・Pages への公開）。取り出した後の手順に、リポジトリの鍵を残さない（`persist-credentials: false`）。依存の既知の弱点は `npm audit` で 0
- **できないこと**：GitHub Pages では応答の見出し（frame-ancestors など）を設定できない。また 109mei.github.io の下のページ（ほかの作品）は、同じ保存領域（localStorage）を使う
